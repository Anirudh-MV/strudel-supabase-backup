Strudel Session Sync

Backs up every strudel.cc session to your own Supabase project as versioned history: each save inserts a new row, except that a session written again within 5 minutes updates its latest row in place. Session name comes from the first // "Title" comment in the code, author from // @author Name (both optional — falls back to pattern id / your backup ID).

Dashboard → Settings → API → Project URL
Dashboard → Settings → API Keys → Publishable key (sb_publishable_…). Older projects still show the legacy anon key (eyJ…) — that works too. Never paste the sb_secret_… (service role) key.
Acts as the default author and scopes the session browser to your rows.
When on, every new URL strudel generates saves a new version automatically — no button needed. Turn it off to only save when you press Sync now.
Test connection does a live read against your table — use it to confirm the URL, key and RLS policy all work before trusting a sync.
One-time Supabase setup — drops and recreates everything
Warning: this deletes all backed-up sessions. Run it once in the Supabase SQL editor, then reload the extension. One table, six columns. 
-- Strudel Session Sync - fresh setup.
-- Drops any previous table/view, then creates the single table this
-- extension needs. Everything lives in one row per saved version:
-- the strudel share URL (the code is inside the URL fragment).
-- Order matters: an older version's view depends on the table, so
-- the view has to go first or the table drop fails with 2BP01.

drop view if exists public.latest_strudel_sessions;
drop table if exists public.strudel_sessions;

create table public.strudel_sessions (
  id bigint generated always as identity primary key,
  session_name text not null,   -- strudel metadata title, else __latest__
  author text not null,         -- your Backup ID; every read filters on this
  url text not null,            -- the strudel link; code lives in the fragment
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index strudel_sessions_author_created
  on public.strudel_sessions (author, created_at desc);

alter table public.strudel_sessions enable row level security;

-- The publishable key (and the legacy anon key) authenticates as the
-- `anon` role, so this policy is what actually gates access. Do NOT
-- reuse this project for other sensitive data - the key ships inside
-- the extension.
create policy "anon all on strudel_sessions"
  on public.strudel_sessions for all
  to anon using (true) with check (true);
